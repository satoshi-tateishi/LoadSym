# シンボル外周に出る余分な枠（Chromium描画現象）調査と対応

配置したシンボルの塗りの少し外側に、状態と無関係な薄いグレーの矩形（角落とし等の非矩形シンボルでも
外接bboxの形で出る）が表示される現象の調査記録と対応。`docs/assets/js/renderer.js` の修正で
1パーツの機材については解消済み。複合形状（パーツ2つ以上）は原因構造が残るため未対応。

## 症状

シミュレーター・機材置き場に置いたシンボルの周囲に、塗りとは別に薄いグレーの矩形の枠が見える。

- 選択枠（青）・要確認（赤）とは別物で、状態を持たない。常に薄いグレー。
- 非矩形シンボル（角落とし多角形など）でも、角落としに沿わず**外接bboxの形**で出る。
- ユーザーの記憶によれば、Phase 1（矩形シンボルのみだった頃）には存在しなかった。

## 原因

`docs/assets/js/renderer.js` の `renderPlacement()` が、1つのシンボルを次の2枚の `<path>` で
描いていたことが原因。

1. `path.fill` … 塗りだけ（`fill-opacity` で半透明）
2. `path.outline` … 線だけ（`fill="none"`、L字・円のツライチ外形線を正しく引くための別パス）

**この2枚目（`fill="none"` の線専用パス）を、半透明の塗りパスに重ねて描くと、Chromiumが実画面へ
合成する際にその周囲へ薄い縁を誤って合成する。** マークアップ自体は正しく、`renderer.js` のバグでは
ない。SVGマークアップをオフスクリーン描画（`data:image/svg+xml` → `<canvas>`）すると再現せず、
**実画面への合成（ライブDOMの描画）だけで起きる**。

### 混入した経緯

`git log` で特定。`989bc55 Draw a symbol as its outline rather than its bounding box`
（Phase 2, L字・円のツライチ外形線を導入したコミット）で、それまで1つの `<rect>`（塗りと線を
同時に持つ）だった描画方式を、上記の2枚重ねへ変更した。ユーザーの「初期実装には無かった」という
記憶と一致する。

## 調査で切り分けた要因（すべて無関係と確認）

Playwrightでスクリーンショットを撮り、Canvas経由でピクセルを直接読み取って切り分けた。

| 試したこと | 枠は？ |
|---|---|
| グリッド・ルーラー・荷台枠をDOMから完全削除 | 出る |
| `<text>` を削除 | 出る |
| `transform` を外し、絶対座標を `path` の `d` に直接焼き込み | 出る（位置も不変） |
| `style="cursor:grab"` を除去 | 出る |
| `fill-opacity` を1（不透明）に変更 | 出る |
| `path.outline` の `fill` を `"none"` から `"transparent"` に変更 | 出る |
| CSS表示サイズだけを変える（viewBoxは同じ） | 出る（view単位での余白は不変。CSS px基準ではない） |
| **`path.outline` を削除し、`path.fill` だけにする** | **消える** |
| `path.outline` を作り直して戻す | 再び出る |

余白はSVG座標（mm相当）で常に一定で、CSS表示サイズや拡大率を変えても変わらなかった。
`document.elementsFromPoint()` で実座標を突き合わせても、枠の位置に一致する要素のジオメトリは
存在しなかった（＝マークアップ上の特定の線ではなく、合成時に生じる現象）。

## 対応

`path.outline` を、**1パーツの機材に限り廃止**し、`stroke` / `stroke-width` を `path.fill` へ
直接持たせる1本の `<path>` に統合した（`symbolPaths()` を新設し、`renderPlacement()` /
`showDropGhost()` の両方から呼ぶ）。

```js
if (drawing.singlePart) {
  return `<path class="fill" d="${drawing.fillPath}" fill="${escapeXml(fillColor)}"` +
    ` fill-opacity="${fillOpacity}" stroke="${strokeColor}" stroke-width="${strokeWidth}"${dash}/>`;
}
```

1パーツ（矩形1枚、または角落とし等の単一多角形・単一円）には内部の継ぎ目が無いため、塗りパスへ
そのまま centered stroke を掛けても見た目は変わらない。実機で角落とし多角形（EKX-12）・矩形
（EKX-15S）の双方について、統合前後で見た目が同じであることをピクセル単位で確認済み。

### 対応しなかった範囲

複合パーツ（L字など、`shape.parts` が2つ以上）は、内部の継ぎ目を消すために
`unionOutline()`（`geometry.js`）による外形線抽出、または `outlineMask()` によるマスクが必要で、
単純に1本の `<path>` へ統合できない。この場合は**従来どおり2本の `<path>` に分けたままなので、
現象は理論上残る**。

ただし対応時点でDBに登録されている機材テンプレートに複合形状（`shape.parts.length > 1`）は
1件も無く、実データでは全ケースが1パーツに該当する。複合形状の機材が登録された場合に再発する。

## 検証

- `npm test`（geometry / packing / shape-editor、246件）は全通過。今回の現象はブラウザの実画面
  合成でのみ再現する視覚的なものなので、Node上のユニットテストでは検出できない。**自動テストは
  追加していない**。
- 実データ（「積み込みテストB」20点、複数回転・複数機材種）で `npm run serve` のポート8090から
  目視・ピクセル確認し、枠が消えたこと、要確認件数が変わらないことを確認した。
- PNG出力（`export-png.js`）はライブSVGを `XMLSerializer` でそのままシリアライズする経路のため、
  修正が自動的に反映される。別対応は不要。

## 動作確認時の注意（キャッシュ）

修正後の確認では、`npm run serve` のポート8090で通常のリロード・新規タブ・
`Ctrl/Cmd+Shift+R` を試しても古い `renderer.js` が読み込まれ続けることがあった
（`curl` ではサーバーが新しい内容を返すことを確認済みなので、サーバー側の問題ではない）。
`127.0.0.1:8090`（`localhost:8090` とは別オリジン扱いになりキャッシュが分かれる）で開き直すことで
切り分けた。実際の開発では、開発者ツールを開いて「キャッシュを無効化」にチェックを入れる操作が
確実（`CLAUDE.md` 記載のとおり）。

## 今後の対応候補

複合形状の機材が実際に登録され、この現象が問題になった場合は次のいずれかを検討する。

- `unionOutline()`（`geometry.js`）が返す辺の集合を、閉ループへチェインして1本の `<path>` に
  組み直す（塗りと線を同じパスに統合できるようになる）。既存の `unionOutline()` の戻り値の形
  （順序を持たない辺の配列）を変えると `geometry.test.mjs` に影響するため、新しい関数として追加
  するか、既存のテストを見直す必要がある。
- 複合形状のみ、2本の `<path>` のまま現象を許容する（現状の対応）。実害が出るまで先送りする。
