## 作業1: 共有モジュール `docs/assets/js/shape-editor.js`（新規）

機材フォームは `simulator.html`（自分の機材）と `admin.html`（共通テンプレート）の2か所にあり、保存処理も別々（`pages/simulator.js` / `pages/admin.js` の `saveEquipment()`）。**エディタは1つ作って両方から使う**こと。片方にだけ実装すると、テンプレート機材に形を付けられない。

Alpineコンポーネントとして作り、`equipmentForm.shape` を読み書きする。

## 作業2: エディタの中身

**描画の向きは荷台と同じにする。** `renderer.js` と同じ写像（ビューX = 奥行き、ビューY = 幅の反転）で描けば、**エディタで描いた形が、回転0で荷台に載ったときの見た目と一致する**。軸には「幅」「奥行」を明記して、数値入力欄との対応が分かるようにすること。

- **グリッド**: 100mm。`Shift` を押している間は 10mm。座標は必ず整数mmに丸める
- **矩形ツール**: キャンバス上のドラッグで1つ追加する
- **選択・移動・削除**: パーツをクリックで選択、ドラッグで移動、`Delete` で削除
- **パーツ一覧**: 右か下に X / Y / 幅 / 奥行 の数値入力を並べ、キーボードでも直せるようにする（既存のトラックフォームの障害物入力と同じ作り方が使える）
- **ライブプレビュー**: 現在の外形bboxの寸法（幅 × 奥行）を常に表示する
- **矩形に戻す**: 形を捨てて `shape = null` に戻す導線を必ず置く。形を付けたあとに戻せないと、間違えたときに機材を作り直すことになる

## 作業3: 保存時の処理

1. パーツを**bboxの左前が原点(0,0)になるよう正規化**してから保存する（`toParts` はbbox基準で回転するので実害は無いが、データを素直に保つ）
2. **bboxから `width_mm` / `depth_mm` を計算して書き戻す**。一覧表示・CSV・並び替え・空き探索の初期サイズがこの値を使っている
3. パーツが1つだけで、かつbbox全体を覆っているなら `shape = null` にする（ただの矩形をわざわざ形として持たない）
4. **パーツどうしの重なりを検出して保存前に知らせる**。重なると配置率の面積が二重に数えられる（`summarize` はパーツ面積の単純合計）。`shapesOverlap` は別々の形の比較用なので、ここは `rectsOverlap` を直接使う
5. 妥当性: 幅・奥行は 1〜20000mm（`equipments` のcheck制約に合わせる）、パーツは1つ以上

`saveEquipment()` の `values` に `shape` を含めること。**現状は含めていない**ので、そのままだと保存されない。

## 作業4: 一覧表示

機材リストの `1770×460×800` のような寸法表示は、形を持つ機材では**外形bbox**の値になる。誤解を避けるため、形を持つ機材には小さな印（アイコンか「L字」等のバッジ）を付けることを検討する。判断は実装者に任せるが、付けるなら簡素に。

## 補足: 小さな片付け（余力があれば）

`geometry.js` の `toRect()` は、Phase 2 で `renderer.js` が使わなくなり、**現在はテストからしか呼ばれていない**。
「マスタ寸法から外形bboxを出す」定義として `boundsOf(toParts(...))` との一致テストに使われているので消す必要はないが、本番から呼ばれていないことをコメントに書いておくと、次に読む人が迷わない。
