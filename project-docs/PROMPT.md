## 作業1: 仕様書の更新（`project-docs/SPECIFICATION.md`）

実装に合わせて次を書く。**「なぜそうしたか」を必ず添える**のがこの文書の書き方。

### 5.1 機材データ

- `shape jsonb`（null = 従来どおりの1枚矩形）を追加したこと
- 形は**軸平行な矩形パーツの集合**。辺が軸平行なら、既存の吸着・押し出し・空き探索の設計をそのまま使えるため
- `width_mm` / `depth_mm` は**外形bbox**として残す（一覧表示・CSV・並び替え・空き探索の初期サイズが使う）。形状エディタが保存時に書き戻す
- `parts[].kind` を最初から持たせてあり、将来の多角形・円はマイグレーション不要
- パーツどうしは重ねられない（重なると配置率の面積が二重に数えられるため）

### 6.2 / 6.3（配置とスナップ / 回転と干渉処理）

- 接触判定は**パーツ単位（辺基準）**。L字の凹みに別の機材が入る
- 吸着候補もパーツの辺から作る。x軸とy軸を独立に評価する構造は変えていない
- 押し出し量は**重なっているパーツ対それぞれの必要量の最大**を採る（1組だけ見ると別のパーツが食い込んだまま残る）
- **壁との判定は外形bboxのまま**。荷台幅いっぱいの機材が「直しようのない赤」にならないよう、`clampToBed` の逃がし方と揃えてあるため
- 回転は90度刻みのまま。形自身のbboxを基準に回す

### 6.5 集計

- **配置率がパーツ面積の合計になった**（従来は外形bbox）。凹み分が引かれ、実態に近づく。矩形だけのレイアウトでは値は変わらない

### 6.4 高さの扱い

- 2.5D拡張の前提として、**すべての形は高さ方向に真っ直ぐ立ち上がる柱**（直方体・多角柱・円柱）に限定すること。
  こうしておくと立体の干渉判定が「2D形状の重なり × 高さ範囲の重なり」に分解でき、今の2D判定をそのまま使える

### 描画（6.1 のあたり）

- 機材1個を「全パーツを1枚のpathにまとめた塗り」＋「unionの境界だけを描いた外周線」で描くこと。
  パーツごとに半透明の矩形を重ねると重なり部分だけ色が濃くなり、境界の内側に線が出ると1個の機材に見えないため
- 当たり判定が形に沿うので、凹みをクリックすると凹みに入っている機材が選ばれる
- **実装上の落とし穴を2つ、短く残すこと**（どちらも今回踏んだ）:
  - `<svg>` の内側では Alpine の `<template x-for>` が使えない（SVG名前空間の要素になり `.content` を持たない）。
    マークアップを文字列で組み立てて `x-html` に渡す
  - `:viewBox="..."` のようなバインドは効かない（HTMLパーサが属性名を小文字化し、SVGは大小文字を区別するため）。
    JSから `setAttribute('viewBox', ...)` で設定する

## 作業2: CSV取り込みの方針を決めて明記する

**推奨: CSVでは形を扱わない。CSVで作られた機材は矩形（`shape = null`）とする。**

理由（仕様書に書くこと）:

- 1行1機材の表形式に複数パーツを畳むと、現場でExcelから書けるものにならない
- 形は図で見ながら作るもので、テキストで書くより形状エディタのほうが速く正確

`docs/admin.html` のCSV説明文にも一言添える（「形状は取り込み対象外です。取り込み後に機材を編集して形を付けてください」など）。
`docs/assets/js/csv.js` は**変更不要**（`shape` 列を足さない、が決定）。
