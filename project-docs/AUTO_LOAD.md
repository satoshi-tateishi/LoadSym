# 自動配置（一括パッキング）実装計画

## 1. 目的

シミュレーターで選んだ1台のトラックについて、そのトラック内に既にある機材を、荷台の左前から自動で詰め直す。

最初から最適解を求めるのではなく、既存の配置判定を再利用した単純で予測しやすいロジックを先に実装し、実際の音響機材データで動作を確認してから、並び順・回転・ラッシングを意識した整列を段階的に調整する。

## 2. 現在のプロジェクトに合わせた前提

- 実装は素の JavaScript（ES Modules）で行う。TypeScript や新しい依存ライブラリは追加しない。
- 配置データは `equipments = [{ width, depth, x, y }]` ではなく、現在の `slot.placements` をそのまま扱う。
  - `placement = { id, equipmentId, snapshot, x, y, rotation }`
  - 寸法・重量・色・複合形状は `snapshot` に保存されている。
- 座標は確定仕様どおり、荷台の左前を `(0, 0)`、`x` を幅方向、`y` を奥行き方向とする。SVG上の横向き表示への変換は `renderer.js` に任せ、自動配置ロジックには持ち込まない。
- 対象はユーザーが操作したトラック1台のみとする。機材置き場、別のトラックとの間で機材を自動移動しない。
- 機材置き場は自動配置の対象外とする。置き場は積み込み前の作業台であり、荷台とはクリアランス・はみ出しの規則が異なるため。
- Viewer は実行できない。Admin / Editor でも、他ユーザーのレイアウトを読み取り専用で開いている間は実行できない。
- 高さと重量は配置順・成否に使わない。パイロット版は確定仕様どおり床面積ベースとする。既存の高さ超過・最大積載重量の警告表示は配置後もそのまま利用する。
- DB変更は不要。自動配置の結果は通常の `placements` として既存のレイアウト保存処理に渡す。

## 3. 初版の仕様

### 3.1 操作対象

- 各トラックの見出しに「自動配置」ボタンを置き、そのトラック内の全機材を対象にする。
- トラックに機材がない場合、または読み取り専用の場合はボタンを無効にする。
- 現在の機材置き場や選択中の機材だけを対象にする機能は初版には含めない。

トラックごとのボタンにするのは、最大3台を同時表示できる画面で対象を取り違えないためである。

### 3.2 単純な配置ロジック

初版は、既存の `geometry.js` にある `findFreeSpot()` を機材ごとに繰り返し使用する。

1. 対象トラックの placements を複製し、元配列・元オブジェクトを変更しない。
2. 各機材について現在の `rotation` を反映した外形 bbox を求める。
3. 外形の奥行きが大きい順、同じなら幅が大きい順、さらに同じなら元の配列順で安定ソートする。
4. 荷台を空の状態として、ソート順に1点ずつ `findFreeSpot()` へ渡す。
5. 探索済みの機材とトラックの障害物を避け、現在の `clearanceMm` を確保できる左前側の最初の候補へ置く。
6. 全点を置いた後、既存の `findInvalidShapes()` で荷台境界・障害物・機材間のクリアランスを最終検証する。`findFreeSpot()` の探索結果だけで成功と決めない。
7. 全点を置けて最終検証も通った場合だけ、新しい placements を返す。返却配列の順番は描画・保存への不要な影響を避けるため元の順番に戻す。
8. 1点でも置けない場合や最終検証で不正が見つかった場合は途中結果を採用せず、元の placements をそのまま返す。

奥行きの近い機材が結果として近い順番で処理されるため、最初の段階でも同程度の奥行きがまとまりやすい。ただし、初版では奥行きの許容差による明示的なグループ分けや、リアゲート側のツライチ評価は行わない。

### 3.3 初版で回転を自動変更しない理由

- 既存の `rotation`（0 / 90 / 180 / 270）を維持する。
- 自動回転まで同時に入れると、「並び順」と「向き」のどちらが結果を悪くしたか切り分けにくい。
- 複合形状は90度回転で利用できる空間が大きく変わり、単純な幅・奥行き比較だけでは良い向きを選べない。

まず配置順だけの結果を確認し、入りきらない実例を集めてから自動回転を追加する。

### 3.4 失敗時の扱い

汎用案にある `isOverflow = true` は追加しない。現在の確定仕様では、通常操作によって荷台からはみ出す配置を新たに成立させず、収まらない操作を棄却するためである。

自動配置も同じ方針に揃え、全点を配置できなければ次のように扱う。

- 座標と回転を一切変更しない。
- 置けなかった placement ID を計算結果に含める。
- UIでは「全機材を収められなかったため、配置を変更しませんでした」と通知する。
- 既存データに赤い機材がある場合でも、自動配置の途中結果で状態を悪化させない。

### 3.5 純粋関数のインターフェース案

`docs/assets/js/packing.js` に、DOM・Alpine・Supabaseを参照しない関数を追加する。

```js
export function autoArrangeSlot(slot, clearanceMm = DEFAULT_CLEARANCE_MM) {
  // 成功:
  // { placements: [...], status: 'arranged', unplacedIds: [] }
  // 座標が初めから同じ:
  // { placements: slot.placements, status: 'unchanged', unplacedIds: [] }
  // 失敗:
  // { placements: slot.placements, status: 'failed', unplacedIds: [...] }
}
```

関数名を `autoArrangeEquipments(equipments, truckWidth, truckDepth)` にしないのは、現在の当たり判定に必要な `rotation`、`snapshot.shape`、障害物、トラック寸法、クリアランスが `slot` にまとまっているためである。

純粋関数の責務は座標計算だけに限定し、履歴への追加、通知、再描画はページ側で行う。

## 4. UIへの接続

`docs/assets/js/pages/simulator.js` にトラックのスロット番号を受け取るハンドラを追加する。

```js
autoArrange(slotNumber) {
  if (this.readOnly) return;

  const slots = this.rawSlots();
  const slot = slots.find((item) => item.slot === slotNumber);
  if (!slot || isStaging(slot) || slot.placements.length === 0) return;

  const result = autoArrangeSlot(slot, this.clearanceMm);
  if (result.status === 'failed') {
    this.notice('全機材を収められなかったため、配置を変更しませんでした。');
    return;
  }
  if (result.status === 'unchanged') {
    this.notice('機材は既に自動配置と同じ位置にあります。');
    return;
  }

  slot.placements = result.placements;
  this.commit(slots);
  this.notice(`${slot.truck.name} の機材を自動配置しました。`);
}
```

空配列・同一座標・失敗は `status` で区別し、不要な履歴を追加しない。成功時は既存の `commit()` を1回だけ呼ぶ。これにより、全機材の移動が履歴上の1操作になり、「元に戻す」で自動配置前へ一度に戻せる。`commit()` 後の再描画には既存の `renderAll()` を利用する。

ボタンには既存のTailwindクラスを優先して使う。新しいクラスを追加した場合は `npm run build:css` を実行し、生成された `docs/assets/css/styles.css` もコミット対象にする。

## 5. 実装手順

### フェーズ1: 最小ロジック

1. `packing.js` に `autoArrangeSlot()` を追加する。
2. `toParts()` / `toShape()` / `boundsOf()` / `findFreeSpot()` / `obstacleShapes()` を再利用し、当たり判定を二重実装しない。
3. 現在の回転を維持したまま、奥行きの大きい順に左前から配置する。
4. 配置後に `findInvalidShapes()` で全体を検証する。
5. 全点配置できない場合や検証に通らない場合は原状維持にする。

### フェーズ2: ユニットテスト

`tests/packing.test.mjs` に少なくとも次を追加する。

- 空のトラックでは変更しない。
- 矩形機材を奥行きの大きい順に左前から配置する。
- 入力の slot / placements / snapshot を破壊しない。
- 現在の回転を維持する。
- ユーザー設定のクリアランスを確保する。
- 荷台幅いっぱいに近い機材では、既存の壁クリアランス例外と同じ結果になる。
- 障害物を避ける。
- L字・円・凸多角形を既存の厳密形状判定で配置できる。
- 全点が入らない場合は途中結果を返さず、元座標を維持する。
- 同寸法の機材で毎回同じ結果になる（安定した決定性）。

ロジック変更後に `npm test` を実行し、geometry / packing / shape-editor の既存テストもすべて通す。

### フェーズ3: UI接続

1. `simulator.js` から `autoArrangeSlot()` を読み込む。
2. `autoArrange(slotNumber)` を追加し、成功時だけ `commit()` する。
3. `docs/simulator.html` の各トラック見出しへ「自動配置」ボタンを追加する。
4. 読み取り専用・空トラックでは無効化する。
5. 成功・失敗を既存の一時通知で知らせる。

### フェーズ4: ブラウザでの動作確認

AGENTS.md の手順どおり、ローカルサーバーは次のコマンドでポート8090に固定して起動する。

```bash
npm run serve
```

ブラウザではESモジュールのキャッシュを無効化するか、ハードリロードして確認する。

確認項目:

- トラック1台と3台の両方で、押したトラックだけが変わる。
- 機材置き場の配置は変わらない。
- 矩形・L字・円・多角形、回転済み機材、障害物ありのトラックで重なりが発生しない。
- 設定したクリアランスが反映される。
- 自動配置後に要確認件数が増えない。
- 1回のUndo / Redoで、自動配置前後を往復できる。
- 自動配置後に保存し、再読込して同じ配置が復元される。
- 入りきらない場合に元の配置が変わらない。
- Admin / Editor では実行でき、Viewerおよび他ユーザーの読み取り専用レイアウトでは実行できない。
- PNG出力・印刷にボタンや通知が写り込まない。

## 6. 動作確認後の調整候補

初版を実データで確認し、問題が観測されたものだけを次の順で追加する。

1. **並び順の調整**
   - 奥行き差が一定範囲内の機材を同じグループにまとめる。
   - グループ内を幅の大きい順にして、列の端の細い隙間を減らす。
   - 元の並び順や機材名には依存せず、同じ入力から同じ結果を返す。
2. **行・列の整列評価**
   - 単に最初に見つかった空きへ置くのではなく、行の終端の凹凸、残り幅、使用奥行きをスコア化する。
   - リアゲート側のラインを揃える要件は、どの辺を揃えるかを実データで確認してから評価式へ加える。
3. **90度自動回転**
   - 現在向きと90度回転の両候補を試し、置ける点数、使用奥行き、空きの分断が良い方を選ぶ。
   - 円や正方形など、回転しても形が変わらない候補は重複評価しない。
4. **複数候補の比較**
   - 「奥行き優先」「面積優先」「幅優先」など少数の決定的な並び順を試し、全点が入る候補の中から使用奥行きが短いものを選ぶ。
5. **必要な場合だけ計算量を抑える**
   - 代表的な最大点数で処理時間を計測し、操作待ちが問題になった時点で候補数や試行数に上限を設ける。

## 7. 初版では行わないこと

- 機材置き場からトラックへの自動積み込み
- 複数トラックへの自動振り分け
- 高さ方向の段積み
- 最大積載重量を考慮した振り分け
- 機材カテゴリ、搬出順、重量物の位置、ラッシングポイントなどの業務ルール
- ミリ秒単位で最適解を探索する外部パッキングライブラリの導入
- DBスキーマや保存形式への自動配置専用フィールドの追加

これらは単純な配置ロジックの実地結果と、現場で優先すべき条件が確認できてから別フェーズとして仕様化する。

## 8. 仕様書の更新

実装時には `project-docs/SPECIFICATION.md` の「6.2 配置とスナップ」または「6.6 操作補助」に、少なくとも次を追記する。

- 自動配置の対象は指定したトラック内の全機材であること。
- 機材置き場と他トラックには影響しないこと。
- 現在の回転を維持し、現在のクリアランスと障害物を考慮すること。
- 全機材が収まる場合だけ確定し、失敗時は原状維持すること。
- 1回のUndoで元へ戻せること。

並び順や自動回転を調整した場合も、確定した挙動に合わせて同仕様書を更新する。
