# 多角形シンボル対応 実装フェーズ

矩形1枚だったシンボルを**直角のみの多角形（矩形パーツの集合）**に拡張し、接触判定を辺基準にするための実装手順。

各フェーズは単体で完結し、そこで止めても壊れない状態になるよう分けてある。

## 前提（決定事項）

| 項目 | 決定 | 理由 |
|---|---|---|
| 対応する形 | **直角のみ**（L字・凹型・T字） | 辺が軸平行なら、既存の吸着・押し出し・空き探索の設計をそのまま使える |
| 形の持ち方 | **軸平行な矩形パーツの集合** | `rectsOverlap` をパーツごとに回すだけで辺基準の判定になる |
| 回転 | **90度刻みのまま** | 壁や隣の機材と辺が平行に保たれ、吸着の考え方を変えずに済む |
| 対象 | **機材シンボルのみ** | 荷台の障害物（タイヤハウス等）は矩形のまま |
| 高さ方向 | **多角柱・円柱に限定**（断面は高さ方向に一定） | 2.5D拡張時に「2D形状の重なり × 高さ範囲の重なり」に分解でき、幾何エンジンを作り直さずに済む |
| 将来の拡張 | エディタに多角形ツール・円ツール | データは `parts[].kind` で受けられるようにしておく |

### 設計の芯: 二層に分ける

- **動きの見積もり（吸着・押し出し・空き探索）** … パーツの**bbox**を使う
- **接触の判定（赤くするか）** … **厳密な形状**を使う

こう分けておくと、将来 円や多角形を足しても厳密判定にペア関数を追加するだけで済み、吸着・押し出しのロジックには手を入れない。円に対して「一番外側に合わせて吸着する」挙動は、現場の感覚とも合う。

## Phase 0: データモデル（見た目は変わらない）

**目的**: 形を保存できるようにし、既存データが1パーツの矩形として扱われることを保証する。

**変更**

- `project-docs/sql/007_equipment_shape.sql`（新規）
  ```sql
  alter table public.equipments add column shape jsonb;  -- null = 従来の1枚矩形
  ```
- `docs/assets/js/equipments.js` … `shape` の読み書きを通す
- `docs/assets/js/layouts.js` … `equipment_snapshot` に `shape` を含める（マスタの形を後から変えても保存済みの図は変わらない。既存のスナップショット方針どおり）
- `docs/assets/js/geometry.js` … `toParts(placement)` を追加。`shape` が無ければ `[{ x:0, y:0, w:widthMm, d:depthMm }]` を返す

**形の持ち方**（外形bboxの左前を原点とするローカル座標）

```json
{ "parts": [
  { "kind": "rect", "x": 0,    "y": 0, "w": 1370, "d": 460 },
  { "kind": "rect", "x": 1370, "y": 0, "w": 400,  "d": 250 }
]}
```

- `width_mm` / `depth_mm` は**外形bboxとして残す**。一覧表示・CSV・並び替え・`findFreeSpot` の初期サイズがそのまま動く
- `kind` を最初から持たせる。多角形（`points`）や円（`cx/cy/r`）を足すときに**マイグレーション不要**

**完了条件**

- `shape` が null の既存機材・既存レイアウトで、図・判定・集計が以前と1mmも変わらない
- SQLをダッシュボードで適用し、`shape` に手でL字を入れた機材が読み込めること（描画はまだ矩形のまま）

## Phase 1: 幾何エンジン（辺基準の判定）

**目的**: 判定・吸着・押し出し・空き探索をパーツ単位にする。ここが本体。

**変更**: `docs/assets/js/geometry.js`（中心）、`docs/assets/js/packing.js`（呼び出し名の差し替えのみ）

**追加する関数**

- `toParts(placement)` → 絶対座標のパーツ配列。回転は90度刻みで適用する。外形が `w0 × d0` のとき:

  | 回転 | 変換 |
  |---|---|
  | 0 | `(px, py, pw, pd)` |
  | 90 | `(d0 - py - pd, px, pd, pw)` |
  | 180 | `(w0 - px - pw, d0 - py - pd, pw, pd)` |
  | 270 | `(py, w0 - px - pw, pd, pw)` |

- `shapesOverlap(a, b, gap)` … パーツ総当たりで `rectsOverlap` が1組でも真なら真
- `boundsOf(parts)` … 外形bbox（壁判定・寸法パネル・ラベル配置に使う）

**直す関数**

- `findInvalidRects` → 形状版。機材どうしは `shapesOverlap`、壁は `fitsInBed(boundsOf(parts))`
  - 壁判定をbboxのままにするのは、「荷台幅いっぱいの機材はクリアランスを諦める」という既存の逃がし方（`clampToBed` と揃えてある）を壊さないため
- `snapPosition` … 候補の作り方だけ変える。移動側パーツの原点オフセット `dx/dy` を引く
  - 隣接: `other.x + other.w + clearance - mp.dx` / `other.x - mp.w - clearance - mp.dx`
  - 整列: `other.x - mp.dx` / `other.x + other.w - mp.w - mp.dx`
  - x軸・y軸を独立に評価する構造は現行のまま
- `computePush` … 重なっているパーツ対ごとに4方向の必要移動量を出し、**方向ごとに最大値**を取ってから既存のスコア評価（はみ出し・軸切り替えのペナルティ）にかける。`lockedAxis` による振動防止はそのまま
- `findFreeSpot` … 候補は既存パーツの辺＋壁ぎわ（`edgeCandidates` をパーツ単位に）。判定を `shapesOverlap` に
- `summarize.floorAreaRatio` … パーツ面積の合計に（凹み分が引かれ、配置率が実態に近づく）
- `clampToBed` / `clearances` … bbox基準のまま

**完了条件**（`tests/geometry.test.mjs` / `tests/packing.test.mjs` に追加）

- L字の凹みに別の機材が入る（外形矩形なら弾かれるケース）
- L字を90度ずつ回したときのパーツ座標が上の変換表と一致（4方向すべて）
- L字への吸着（袖の辺に付く / 本体の辺に付く）
- L字を押し出したとき、凹み側へ逃げられること
- `findFreeSpot` が凹みを空きとして見つけること
- **既存テストが1つも壊れないこと**（矩形は1パーツの特殊ケースとして通る）

## Phase 2: 描画

**目的**: L字がL字に見えること。1個の機材として見えること。

**変更**: `docs/assets/js/renderer.js`

- パーツごとに `<rect>` を塗り、その上に **union outline（外周線）だけを線分で描く**
  - パーツ境界の内側に線が出ると1個の機材に見えない
  - 矩形の集合なので、各パーツの4辺から「他パーツの内部に入る区間」を除いた線分を残すだけで求まる（30行程度）
  - 選択枠の青、エラーの赤も同じ線分群を使う
- ラベルは**最大パーツの中心**に置き、そのパーツのboxで `chooseLabel` を呼ぶ（縦横の判定は現行のまま）
- `updatePlacementPosition` / `showDropGhost` … 全パーツの座標を書き換える方式にする（パーツ数は数個なのでコストは無視できる）。ドラッグ中にDOMを作り直さない原則は維持

**完了条件**

- L字・凹型が正しい外形で描かれ、内部に余計な線が出ない
- 選択枠・エラーの赤・ドラッグ中の追従・移動先ゴーストが形どおり
- PNG書き出しと印刷でも同じ見た目

## Phase 3: 形状エディタ（矩形ツール）

**目的**: SQLを書かずに画面から形を作れるようにする。

**変更**: `docs/assets/js/shape-editor.js`（新規・共有モジュール）、`docs/simulator.html` と `docs/admin.html` の機材フォーム

機材フォームは2か所にあるので、**共有モジュール**にして両方から開く。

- 既定は今までどおり幅×奥行の数値入力。「形を編集」でエディタを開く
- SVGキャンバス、100mmグリッド吸着（Shift で 10mm）
- **矩形ツール**: ドラッグで追加 / 選択して移動・削除。パーツ一覧を横に出して数値でも直せる
- 保存時にbboxを計算して `width_mm` / `depth_mm` に書き戻す
- パーツどうしは重ねさせない（重なると面積が二重に数えられる）。検出したら保存前に知らせる

**完了条件**

- 画面だけでL字の機材を新規登録し、荷台に置いて回転・ドラッグできる
- 編集して形を変えても、**既に保存したレイアウトの図は変わらない**（スナップショット）
- Editor / Admin の両方の画面から使える

## Phase 5（将来）: 多角形ツール・円ツール

- `parts[].kind` に `polygon` / `circle` を追加（**マイグレーション不要**）
- `shapesOverlap` にペア判定を足す（円×円は距離、円×矩形は最近点、多角形はSAT）
- 吸着・押し出し・空き探索は**パーツのbbox**を使い続ける（上の二層設計）
- エディタに多角形ツール・円ツールを追加。**傾斜のある立体は作らせない**（次のフェーズの前提）

## Phase 6（将来）: 2.5D（段積み）

- すべての形は**高さ方向に真っ直ぐ立ち上がる柱**（直方体・多角柱・円柱）に限定してあるので、立体の干渉判定は「**2D形状の重なり × 高さ範囲の重なり**」に分解できる。Phase 1 の2D判定をそのまま使う
- `height_mm` はシンボル全体で1つの値のまま。パーツごとに高さを変えたくなったら `parts[].h` を足す（各パーツは柱のままなので判定式は変わらない）
- スキーマ上の準備（`stackable` / `max_stack_load_kg` / `stack_level` / `stack_parent_id`）は既に入っている
